# Android 专用渲染（0.7）

仅当存在 Sts2Android 原生桥时启用；普通网页保留原循环。统一 rAF 顺序为核心补间 → Spine/舞台/粒子 → dirty DOM。FPS 上限由调度器负责，避免多个限帧器叠加；后台跳过，恢复重置时间。核心每帧只确定一次 TimeScale，Pixi 不再另设 100ms 的时间截断；粒子自身的稳定性步长限制保留。

不跨 DOM 强行合并图层。战斗与全局特效、受伤红边第一次有需求才申请 renderer，空闲隐藏且不绘制，复用缓存 renderer。初次 shader 编译仍可能产生长帧，需要真机诊断；目前没有把全部战斗 UI 迁到 Pixi，也没有保证始终只有一个 GL 上下文。

原生资源缓存只存小文本，单项≤256 KiB，总计≤8 MiB；图片/音频/字体流式读取。固定 HTTPS origin 和存档存储保持原样。版本 ETag 强制重验证，shouldInterceptRequest 不保证 WebView HTTP 缓存；实际复用来自显式有界缓存。

设置 → 通用 → 性能诊断导出报告。先战斗约半分钟，再打开设置导出，保留 WebView 版本、统一时钟的实际间隔与同步 JS 耗时、最近一分钟长任务（最多120项）、舞台绘制间隔及原生 Window 有界帧统计。JS 同步耗时、Window TOTAL_DURATION 和 intended-vsync 间隔均不能当作 GPU 执行耗时或直接断定瓶颈。报告不包含存档，导出不修改游戏数据。

复测：APK=1 CHROME=/usr/bin/chromium URL=<服务> node tools/e2e/{continue,touch,transition-flash}.mjs <输出目录>；android-render.mjs 需开发服务用于检查实际 Spine 与 core 时间并导出诊断；android-fx-budget.mjs 检查懒创建/红边像素/空闲绘制。核心 android-clock.test.ts 验证帧顺序、30/60/不限帧、后台恢复及帧内 TimeScale。

2026-10-10 验证：核心16文件99测试通过，包含真实旧存档；APK路径保存退出后继续通过。实际战斗Spine在1倍与0.25倍时间尺度下均匹配核心时间，计算须保留原作0.9–1.1的随机待机轨道速度。返回地图1109个合成采样帧白色比例最大0。隔离受伤/全局特效初始0画布，红边采样28处、白色0；全局特效活动7次绘制，退场后0次。以上是云端浏览器正确性检查，不是骁龙865性能基准；未启动Android应用。

完整diff存档审查：未改DTO、模型ID、user://文件名、来源、存储后端或旧数据迁入；改动涉及运行时帧调度，因此通过旧档测试与实际保存继续共同验收。诊断复用系统导出入口但不读取存档；新增并发导出保护，避免备份与诊断同时请求互相误报。

APK构建成功，版本码7；触控长按、取消、攻防出牌与商店预览购买单独复测全部通过。云端SwiftShader并发执行两个完整游戏时，2秒触控等待曾超时；同产物单独运行通过，不把并发软件GPU数据作为真机帧率。
