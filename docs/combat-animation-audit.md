## 分层状态机

- 战斗流程：地图 → 转场遮蔽 → 资源准备 → 开场 → 玩家回合 ↔ 敌方回合 → 死亡收尾 → 奖励 → 地图。
- 每张卡：牌堆 → 发牌 → 手牌 → 聚焦 → 拖拽/瞄准 → 排队 → 出牌 → 弃牌/消耗/能力；取消返回手牌，选牌和重复施放有独立分支。
- 每个生物：待机 ↔ 攻击/施法/受击 → 死亡；格挡、状态、意图、充能球为并行反馈，不能要求所有事件都有骨骼动作。
- 界面：隐藏 → 进入 → 可交互 → 退出 → 销毁。逻辑结果立即提交，显示过渡可延续；退出动画完成前不能先卸载节点。

当前没有统一的视觉准备屏障：`ui/combat.tsx:66` 分别启动背景加载和 stage.mount；`render/stage.ts:570` 又分别加载骨骼及附属特效。规则的场景创建/转场完成不等于画面可呈现。黑幕本身 Normal 有 1.1 秒退出及 0.8 秒进入，不能把这些主动等待算成同步加载。

## 每个转移的验收契约

记录触发事件、旧/新状态、首帧时间、当前屏幕姿态、目标姿态、完成/取消原因、相关资源 ready 时刻。六个条件：

1. 从当前可见姿态开始；跨父节点保留位置、旋转、缩放与透明度。
2. 一次转移只有一个变换所有者；被打断的 Tween 不先快进到终点。
3. 时间由共同逐帧时钟推进；Fast/Normal 下视觉与规则节奏协调。
4. 关键资源和首帧 ready 后才揭幕；明确区分主动遮蔽与主线程长帧。
5. 退出动画画完再移除；取消、死亡、切房间都有收尾，不影响规则与旧存档。
6. 按真实触屏测试每条边，包括成功出牌、选择/取消、重复出牌、洗牌、末张牌击杀和下一场；不以静态截图或已有函数替代。

优先修复：成功出牌姿态丢失 → 选牌与洗牌硬切 → 视觉准备屏障/奖励退出生命周期 → 空动画与 FastMode 节奏 → 按剖析证据处理死亡/特殊效果长帧。使用现有表现层增加少量协调，不重写规则状态机，不引入新动画框架。
