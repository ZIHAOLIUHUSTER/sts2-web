# Android 性能诊断（2026-10-09）

用户设备：骁龙 865、8 GB 内存、2560×1600 屏幕。当前没有证据说明它的硬件不足；优先检查重复渲染、实际渲染分辨率、WebView 版本和驱动。以下是云端 Chromium 的资源诊断，不是这台平板的实测帧率。

## 已测资源大头

对 v0.2 构建运行 `tools/e2e/mobile-performance.mjs`，独立浏览器配置，菜单→首张地图→首场战斗→地图/战斗切换三次。音量、图片、特效保持原样。

| 场景 | GC 后 JS heap | WebGL 纹理基础层估算 | 解码音频缓存 |
| --- | ---: | ---: | ---: |
| 主菜单 | 29.4 MiB | 15.0 MiB | 5.0 MiB |
| 首张地图 | 37.6 MiB | 120.6 MiB | 26.9 MiB |
| 首场战斗 | 40.5 MiB | 145.0 MiB | 43.6 MiB |
| 第三次地图 | 45.5 MiB | 95.8 MiB | 27.9 MiB |

纹理和 PCM 比规则层 JS heap 更值得关注。不同时间点会因正常缓存回收而下降；三次切换不足以证明没有长局泄漏。

优化后以同一路线复测：首场战斗 JS heap 40.1 MiB、纹理基础层 145.1 MiB；第三次回到战斗为 40.6 MiB、76.2 MiB。新增统计显示战斗活动音源的唯一 PCM 约 103–105 MiB，**48 MiB 只限制闲置缓存，不能限制正在播放的音乐**。这些资源量接近基线，符合本次保留画面和声音、减少无谓调度及并发重复解码的目标；没有证据宣称整机内存降低某个百分比。此次每点帧采样为 1 秒，基线为 3 秒，且云端其他测试并发，不能用于帧率前后比较。

- 全部 20 张图集的基础 RGBA 数据约 **146 MiB**，其中八页卡面约 **119 MiB**。3358 张独立纹理全部展开约 **1755.5 MiB**，它们不会同时加载，不能当作实际常驻内存。
- 最大角色选择纹理是 Defect 的 3366×3018，单张展开约 **38.8 MiB**；Ironclad 3713×2427 约 **34.4 MiB**。小体积 WebP 不等于低解码或低 GPU 占用。
- 2560×1600 的一个 RGBA 缓冲约 **15.6 MiB**，深度、多重采样、临时效果和多个 WebGL 画布会放大开销；透明或移出 DOM 的渲染循环仍可能耗 CPU/GPU。
- JS heap 不包括解码图片、PCM、驱动、合成器等。纹理估算不含 mip、帧缓冲及驱动副本；音频缓存与活动音源引用的 buffer 有重叠。**不要把这些列直接相加声称进程内存。**

优先顺序：修正未显示/错位的纹理与兼容性；合并重复动画循环并停掉离开屏幕的渲染；合理控制实际像素数；减少闲置资源引用和重复解码。避免通过删特效、降音质掩盖问题。

## 最低配置的结论与边界

尚未测出可承诺的最低内存或最低芯片型号，不能用云端的 SwiftShader 软件 GPU 推导手机性能。本次云端帧间隔也不能和骁龙 865 的实际帧率比较。

- 安装要求：Android 8.0+（APK `minSdkVersion=26`）、OpenGL ES 3.0；实际还需可用的 WebGL 2，以及 `MAX_TEXTURE_SIZE ≥ 4096`，因为已有纹理边长达到 4096。
- 系统版本老不一定无法运行，**Android System WebView 的版本及 GPU 驱动行为**同样关键；先更新系统允许的 WebView，再复测贴图和卡顿。
- **4 GB** 可作为下一轮低内存机型验证起点，**6 GB+** 作为试用建议；这不是经过真机验证的最低/推荐配置。**2–3 GB** 暂不保证长局稳定。8 GB 设备卡顿应先定位渲染和兼容性，不能直接归因于 RAM。
- 芯片以能力和实测帧时间判断，不给未经测试的 Snapdragon/Dimensity 型号门槛。固定场景、相同帧率设置和分辨率，在实际设备运行后才可发布支持名单。

## 复测方式

```bash
CHROME=/usr/bin/chromium URL=http://127.0.0.1:47174/ \
  node tools/e2e/mobile-performance.mjs /tmp/mobile-performance
```

脚本记录 GC 前后 JS heap、DOM 数、纹理上传基础层估算、解码音频状态、rAF 帧间隔及截图。只连稳定构建，避免 HMR；图像请求量是累计资源估算，不是驻留量；GC 为诊断用途，不代表正常游戏节奏。脚本不读取或修改真机存档。

真机需记录 Android/WebView 版本、GPU 渲染器、实际画布像素数；在菜单、地图、战斗、商店及连续游玩后采样。`adb shell dumpsys meminfo` 应同时检查应用与 WebView renderer 进程，单看 Java heap 或宿主进程会漏算。帧时间用 WebView Performance/Perfetto 记录，`gfxinfo` 不能独自代表 WebGL 内部动画。报告峰值 PSS、持续帧时间、温度和是否发生重载/黑屏，再确定最低配置。
